B 树与 B+ 树：插入分裂，删除借和并

m 阶 B 树一步步插入、删除：上溢就把第 ⌈m/2⌉ 个关键字往上提，下溢先看兄弟够不够借，不够就和父关键字一起合并，都可能一路连到根。每步标出是哪种情况。树形取自罗素讲义第七章 查找 p50–96（B+ 树 p97–99）、强化第三讲 PPT p55–68 和王道《数据结构》7.4 节习题；B 树统考考过 2009、2012–2014、2016–2018、2020–2023、2025 年。

五句话

  1. m 阶 B 树：每个结点最多 m 棵子树、m − 1 个关键字；根以外的结点至少 ⌈m/2⌉ 棵子树、⌈m/2⌉ − 1 个关键字；根至少 1 个关键字。所有叶子在同一层，n 个关键字的结点有 n + 1 棵子树。
  2. 插入一定先落到最底层的叶子。插完关键字数 ≤ m − 1 就结束；等于 m 就上溢：第 ⌈m/2⌉ 个关键字上移到父结点，左右两半各成一个结点。父结点又满了就接着分裂，分到根时根一分为二、上来的关键字成新根，树高 + 1。
  3. 删非终端结点的关键字：用它的前驱（左子树最右下）或后继（右子树最左下）替代，转成删叶子里的那个关键字。
  4. 叶子删后不少于 ⌈m/2⌉ − 1 个：直接删（讲义 type1）。少了就是下溢：相邻兄弟关键字数 ≥ ⌈m/2⌉ 就借：父结点里夹在中间的关键字下移，兄弟最靠近的那个关键字上移补位（type2）。
  5. 兄弟都只有 ⌈m/2⌉ − 1 个就合并：被删结点、兄弟、父结点里夹在中间的关键字合成一个结点（type3）。父结点少了一个关键字又可能下溢，同样先借后并往上调；根被并空了，合并出的结点当新根，树高 − 1。
例题：

每个矩形是一个结点，一格一个关键字，连线从关键字之间的“指针位置”引出。橙色是正在处理的结点或关键字，绿色是刚调整好的，红色是上溢、下溢或要删的，蓝色虚线框是被看的兄弟。最底层空指针（失败结点）没画，树高也不算它。

m 阶 B 树m 阶 B+ 树（王道和讲义的定义）
关键字和子树n 个关键字的结点有 n + 1 棵子树n 个关键字的结点有 n 棵子树，每个关键字对应一棵（是那棵子树里的最大关键字）
非根结点关键字数⌈m/2⌉ − 1 ≤ n ≤ m − 1⌈m/2⌉ ≤ n ≤ m
根结点1 ≤ n ≤ m − 1；不是叶子时至少 2 棵子树1 ≤ n ≤ m；不是叶子时至少 2 棵子树
关键字出现几次每个关键字只出现一次，散在各层结点里叶子里有全部关键字；分支结点里的关键字在叶子里还会再出现
非叶结点存什么关键字 + 记录的存储地址，本身就有数据只起索引作用：只有关键字和子树指针，没有记录地址
查找成功停在哪可能停在任何一层（不一定到叶子）一定查到叶子，每次查找路径一样长，性能稳定
顺序查找、范围查找不支持顺序查找，范围查找要靠中序遍历来回走叶子按关键字从小到大用指针链成链表，可以从最小关键字顺序查找；有根指针和叶链头指针两种查法
用在哪多路查找，文件索引数据库索引、文件系统索引（2017 统考），磁盘读写代价更低

两者共同点：都是平衡的多路查找树，都能随机查找，插入删除都可能分裂、合并，都可用于文件索引。
