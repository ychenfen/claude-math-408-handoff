设备分配与 SPOOLing：一台打印机串起第 5 章后半

同一台打印机看四遍。① 一次 print 请求从用户层走到硬件，重点看设备独立性软件和设备驱动程序怎么分工；② 设备独立性软件给 P1 分配这台打印机，顺着 LUT → SDT → DCT → COCT → CHCT 一路查下去；③④ 用 SPOOLing 把这台独占的打印机变成“大家都能用”的虚拟设备，输出和输入两个方向都照五章的逐页动画走。系统调用、中断响应的细节在“I/O 全链路”页，这里不重复。

    对照表

    表一　设备按“能不能同时给几个进程用”分三类（五章 p35）

    独占设备共享设备虚拟设备
    定义一个时段只能分配给一个进程可同时分配给多个进程；宏观上同时使用，微观上交替使用用 SPOOLing 把独占设备改造成虚拟的共享设备，可同时分配给多个进程
    例子打印机磁盘采用 SPOOLing 实现的共享打印机
    分配时要注意分给一个进程后，别人要用只能等它释放（本页整理）不需要给某个进程独占（本页整理）真正占着打印机的只有系统的输出进程，用户进程分到的是输出井里的一块空间（本页整理，依据 p77–86）

    表二　没有和有 SPOOLing 时，P1、P2 先后要打印

    没有 SPOOLing（打印机按独占设备分配）有 SPOOLing
    P1 请求时打印机正忙P1 挂到打印机 DCT 的设备阻塞队列，等打印机释放（场景 ② 的“设备忙”）P1 不等：打印任务放进磁盘输出井就继续运行（p78–79）
    P2 接着请求也排进设备阻塞队列，要等 P1 用完任务2 排在输出井里任务1 的后面，P2 也继续运行（p80）
    谁在控制打印机分到打印机的用户进程（经驱动程序）系统的输出进程（p77“输出进程（控制输出）”）
    打印机空出来以后唤醒设备阻塞队列里的进程，再分配（本页整理）打印完成发中断 → 唤醒输出进程 → 取输出井队首任务（p81–83）
    谁会阻塞等打印机的用户进程只有输出进程：送出一个任务后自阻塞等打印完成（p86）
    代价—要外存（输入井、输出井在磁盘上）；输入进程、输出进程和用户进程并发运行，要多道程序设计支持（p75、p97 真题 A、B 两项）

    表三　分配方式两组概念（五章 p36–38）

    做法优点缺点
    安全分配为进程分配一个设备后就把进程阻塞，本次 I/O 完成后才唤醒（PPT 以请求打印机打印输出为例）破坏“请求和保持”条件，不会死锁对一个进程来说，CPU 和 I/O 设备只能串行工作
    不安全分配发出 I/O 请求、分到设备后进程继续执行，还可以再发新的请求；只有某个请求得不到满足时才阻塞计算任务和 I/O 任务可以并行，进程推进快可能死锁（要用死锁避免、检测和解除）
    静态分配进程运行前分配全部所需资源，运行结束后归还破坏“请求和保持”条件，不会死锁资源占用时间长、利用率低（本页补充）
    动态分配进程运行过程中动态申请设备用到才申请，利用率高（本页补充）要配合分配算法，防止死锁（本页补充）
