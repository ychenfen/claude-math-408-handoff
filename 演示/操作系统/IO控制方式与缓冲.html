I/O 控制方式与缓冲

“I/O 全链路”页已经把 scanf、read、缺页三条链路一层一层走过了，这里不再重复那些步骤，只做两件事：把同一个读任务放在三种控制方式下并排计时，看 CPU 到底被占了多少；再把单缓冲、双缓冲按块画成时间线，算出处理 n 块的总时间，并和 PPT 的公式对上。最后是缓冲池和循环缓冲区的小动画。

一、同一个任务，三种控制方式：从设备读 N 个字到内存

  1. 轮询：每次读一个字，对读入的每个字，CPU 循环检查设备状态，直到这个字已经在 I/O 控制器的数据寄存器里，再由 CPU 取走。CPU 与 I/O 设备串行工作。（五章 p50）
  2. 中断：设备独立完成对自身寄存器的读写，完成后向 CPU 发中断，由 CPU 完成设备寄存器与内存的数据交换，数据要借助 CPU 的寄存器，CPU 仍参与具体传输。仍是每个字一次中断。（五章 p51；逐层过程见“I/O 全链路”页场景 ①）
  3. DMA：以数据块为基本单位，CPU 发出传输命令（初始化方向、磁盘地址、内存地址、长度）后由 DMA 控制器完成，不需要 CPU 参与，整块传完才中断一次。（五章 p52、p54–59；强化3 p99–105）

单位是“时间单位”，可以当作 μs。PPT 没给这一部分的数值，默认数据和下面的计时模型是本页补充：轮询时每个字 CPU 一直查状态到字准备好，再花 tx 取走；中断方式下中断处理程序花 ti 把字搬进内存并启动下一个字；DMA 每块先花 ts 初始化，块传完花 ti 处理一次中断。DMA 传送时偷用总线的几个周期忽略不计。

CPU 忙于这次 I/O（启动、取数、中断处理）CPU 在轮询，空转查状态CPU 可以执行其他进程设备准备一个字DMA 控制器把一块逐字送进内存中断发生

二、单缓冲和双缓冲：T 输入、M 传送、C 处理

  1. T：数据从 I/O 设备输入到缓冲区；M：从缓冲区传送到工作区；C：CPU 在工作区处理。（五章 p17–18）
  2. 同一个部件的使用必须互斥：缓冲区在 T 和 M 时都被占着，工作区在 M 和 C 时都被占着。这是算时间的唯一规则。（五章 p18 “计算缓冲时间的注意事项”）
  3. 单缓冲：缓冲区被 M 取空后才能输入下一块；双缓冲：设备可以往另一个缓冲区输入，C 与 M 可以和 T 并行。（五章 p19–28，p26 页眉手写“C 与 M 可以与 T 并行”）
换一组：
T 输入M 传送（同时占缓冲区和工作区）C 处理行的画法照 PPT p30–31：T 画在 I/O 设备行，M 画在它取数的缓冲区行，C 画在工作区行。

循环缓冲区（五章 p32）

缓冲区构成一个循环，in 指向输入位置，out 指向输出位置，类似管道和循环队列。初始状态照 PPT：in = 5，out = 12，绿色是已装数据的格子（12～15、0～4），蓝色是空格子。
