## 知识点与适用条件

- **页表自映射（2024-45 的新点）**：页表本身也放在进程的虚拟地址空间里，所以同一个页表项有两个地址：虚拟地址（操作系统改页表时用）和物理地址（MMU 查表时用）。页表所在的那一页，由页表里“指向自己页框”的那一项来映射。
- **开机到第一个用户进程**（强化1 场景 1，强化1 p14 分区画法）：物理格式化（划扇区，扇区含 ID／GAP／DATA）→ 分区（MBR 里有分区表）→ 逻辑格式化（各分区建文件系统）→ 安装 OS。开机：BIOS 自检后读 MBR → MBR 的引导程序找到系统分区，读该分区的 PBR → PBR 装入 OS 内核。之后初始化向量表、页表、就绪队列、超级块、设备表等，再创建第一个用户进程。“有两个系统分区时选哪个（活动分区、开机菜单）”是演示页的补充，PPT 没讲。
- **打开文件的磁盘 I/O**：open 按路径逐级读目录的 inode 和目录块，找到目标文件的 inode 后建系统级和用户级打开文件表。第二个进程打开同一文件时，系统级表项访问计数 +1；各进程有自己的文件指针；close 时计数减到 0 才删表项。
- **I/O 全链路**：一次 read 读文件要经过系统调用（陷入内核）→ 文件系统 → 驱动设置 DMA → 进程阻塞 → DMA 完成发中断 → 中断处理程序唤醒进程 → 进程再次被调度后返回用户态。缺页换入走的是类似的路径，只是由缺页异常而不是系统调用触发。
- **模型语境**：系统调用传参（强化1 用 R0–R3，基础一章 p86–88 用 AX/BX/CX）、INT 0x80、系统调用表、idle_proc、plic、NEED_RESCHED 都是 PPT 的教学模型，不当通用结论。强化4 超级块例子里 inode 大小 4B 是 PPT 的设定。

## 闭卷自测

### 自测：开机时 BIOS、MBR、PBR 各做什么？

**题干**：一块磁盘分成三个分区，每个分区开头各有一个分区引导记录 PBR，其中分区 1 装了操作系统；磁盘 0 号扇区是主引导记录 MBR。按开机顺序说出：(1) BIOS 做什么，从哪里读下一段程序？(2) MBR 里有哪两样东西，它怎么决定去读哪个 PBR？(3) PBR 做什么？(4) 为什么不让 BIOS 直接装入操作系统内核？题源：10-13 16:45、18:07 讲的“从空白磁盘到第一个用户进程”，本卡是局部复习。

**参考要点**：
- (1) BIOS 在 ROM 中，开机后自检硬件，然后把磁盘 0 号扇区的 MBR 读入内存并跳过去执行。
- (2) MBR 有主引导程序和分区表；主引导程序查分区表，找到要启动的系统分区（如活动分区），读入该分区的 PBR。
- (3) PBR 里的引导程序认识本分区的文件系统，找到操作系统内核文件，装入内存并转去执行。
- (4) BIOS 不了解各分区的文件系统，也不知道装了哪个系统；三级接力让每一级只做自己知道的事。
- “活动分区、开机菜单”是演示页的补充说明，PPT 没讲。

### 自测：迁移｜open 一个三级路径，要读几次磁盘？

**题干**：某 Unix 类文件系统，每个目录的内容只占 1 个磁盘块；open 时要读入路径上每一级目录的 inode 和目录块，最后读入目标文件的 inode（不读数据块）。内存中原来没有任何 inode 和目录块。进程执行 open("/home/os/list.db")。(1) 一共读几次 inode、几次目录块？(2) 如果根目录的 inode 常驻内存，共读几次磁盘？(3) 另一个进程随后也 open 同一个文件，系统级打开文件表会怎样变化？本题条件自拟，不是 PPT 原例，数字和 PPT 例子不同。

**参考要点**：
- (1) 根 inode → 根目录块（找到 home）→ home 的 inode → home 目录块（找到 os）→ os 的 inode → os 目录块（找到 list.db）→ list.db 的 inode。inode 4 次、目录块 3 次，共 7 次。
- (2) 根 inode 不用读，共 6 次。
- (3) 系统级打开文件表里该文件的表项不新建，访问计数 +1；第二个进程在自己的用户级打开文件表里新增一项，有自己的文件指针。
- 方法：沿路径列出“inode → 目录块”交替序列，最后一级只读 inode。

### 自测：迁移｜第 326 号 inode 在哪个磁盘块的第几个？

**题干**：某文件系统的磁盘块大小为 4KB，每个 inode 占 128B。inode 区从 2 号磁盘块开始连续存放，inode 从 0 开始编号，块内位置也从 0 开始数。第 326 号 inode 在几号磁盘块、块内第几个？如果 inode 区共 64 块，最多能有多少个文件？本题条件自拟，不是 PPT 原例（强化4 超级块例子用的是另一组设定）。

**参考要点**：
- 每块放 4KB ÷ 128B = 32 个 inode。
- 326 ÷ 32 = 10 余 6：在 inode 区的第 10 块（从 0 数），即磁盘块 2 + 10 = 12 号，块内第 6 个。
- 最多 64 × 32 = 2048 个 inode，即最多 2048 个文件。
- 易错：忘了加 inode 区的起始块号；编号从 0 还是从 1 开始要先看清。

### 自测：一次 read 读磁盘（DMA），进程状态和 CPU 怎样变化？

**题干**：进程 A 调用 read 读文件的一个块，内核缓存中没有这个块，磁盘采用 DMA 方式。按时间顺序说出：(1) 从 read 到数据读完，CPU 在哪几步处于内核态、哪几步可以去运行别的进程？(2) 进程 A 的状态怎样变化，分别是谁让它变的？(3) 整块传输过程中 CPU 被中断几次？题源：10-13 16:45 的 I/O 全链路（强化4、强化3 相关页），本卡是局部复习。

**参考要点**：
- read 是系统调用，A 陷入内核态；文件系统查打开文件表、算出磁盘块号，发现缓存未命中。
- 驱动程序设置 DMA 控制器（内存地址、磁盘块号、字节数）后启动磁盘；A 由运行变阻塞，调度程序选别的进程运行。
- DMA 在磁盘和内存之间直接传完整块，整块完成后才发 1 次中断。
- 中断处理程序（内核态）检查完成情况，唤醒 A（阻塞 → 就绪）；A 被调度后（就绪 → 运行）把数据交给用户缓冲区，read 返回用户态。
- 对比：中断方式每个字（字节）中断一次；程序查询方式 CPU 一直忙等。
