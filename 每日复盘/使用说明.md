# 各科助手的每日总结与复盘

## 每次问答

只维护当前科目。先读取本学科历史交接和最近问答，以北京时间追加到`问答记录/科目/YYYY-MM-DD.md`。每条写：时间和题目／教材版本、用户原问题／作答、答复与纠正、来源和核实程度、是否独立重做。图片未上传则明确缺失，不假称已看原图。

讲题的小节标题写成`## HH:MM　`编号`　题意`，并写`**题**：`完整题干（含选项、关键条件；有图就存图），这样日终写自测卡时题面有据可查；只写“第六题我选C”就无从出题。涉及具体题目时，在小节标题或首行写题目`编号`（沿用此前复盘里的编号），并写明：是否先看过答案或提示、作答是文字还是图片、本次是谁核对的。重做时写明编号、是否独立、作答全文或原图位置，复盘的作答记录要能逐项引用。

## 当我说“总结今天”

先读该科当天全部记录，再按`模板.md`写到`每日复盘/科目/YYYY-MM-DD.md`。必须包含：

1. 今天实际涉及什么：按题或主题列出，计划与完成分开。
2. 题目状态：每道涉及的题一行，按下方规则填状态和证据；先读最近一份复盘的状态表和“下次先做”，接着写。
3. 知识点：定义、适用条件、方法和边界，不只给章节名。
4. 我的卡点与错因：引用我具体的提问或作答；助手推测明确标注。
5. 需要纠正的旧结论：不能因已上传就重复错误。
6. 闭卷复盘：3～5个问题。每题使用`### 自测：问题`，后接`**题干**：…`与`**参考要点**：…`。题干必须能脱离上下文独立作答：写出对象、条件、变量含义、所求，涉及代码／图表就附必要内容；不能只写“第22题”“这道题”。编号只作来源，不能替代题面。题干先展示，只有参考要点及其后内容折叠隐藏；不要把解法提示混入题干。原题、题意整理、局部复习与改编题要标清，缺失条件／原图如实标注，不编造原题。至少一题是迁移题：改变条件或换一种问法，检验能否选对方法，而不是复述刚看过的更正。
7. 下一步：最多3项，可执行到具体题／步骤，未做的不能打勾。
8. 证据来源：链接当天问答。缺少真实记录时不生成假日报。

已有2026-10-05操作系统、数据结构、计算机网络复盘是依据当前仓库记录整理。原作答照片与原教材不全，评价保留“当时助手认为”，不冒充重新判卷。

## 题目状态与升级规则

状态不手工评定，而由「作答记录」逐次推出；表里写的状态必须与推出结果一致，否则测试失败。

| 状态 | 什么情况下成立 |
|---|---|
| 仅安排 | 只出现在计划里，没有讨论和作答 |
| 已讨论 | 问过、看过讲解或解析，没有作答记录 |
| 作答待核实 | 有作答，但最近一次不是“独立＋正确＋原件已核” |
| 独立做对 | 最近一次是“独立＋正确＋原件已核”，且之前没有更早日期的作答 |
| 隔日重做通过 | 最近一次是“独立＋正确＋原件已核”，且日期晚于这道题此前某次作答 |

作答记录每行字段：

- 作答方式：独立／有提示／看答案后／未注明／未作答。只有“独立”可能升级；“有提示”“看答案后”“未注明”都不行；“未作答”（如仅计划重做）不算作答，也不能填作答内容和核对结果。
- 作答内容／附件：有作答就必须写。核对依据为“原件已核”时，必须链接仓库里存在的作答全文或原图。
- 核对结果：正确／部分正确／错误／未核对。“独立作答但错误”停在作答待核实，并在卡点一栏写新错在哪里。
- 核对依据：原件已核／仅旧助手判断／未核对。旧助手说“全对”最多记“仅旧助手判断”。
- 来源：链接本科当天问答小节；作答日期取来源文件日期，不能晚于复盘日期。

`python3 scripts/ledger.py 科目`只检查这些证据字段是否齐全、状态是否与之相符，不能判断答案本身对不对；正确性仍要人或助手对照原件核对。

- 同一编号在不同日期复盘里各写一行，保留历史；网页和脚本只显示最新一份复盘的状态，并列出逐日轨迹。
- 复习间隔只是建议：独立做对后隔1～3天重做；通过再延长，错了就缩短。“下次先做”每天最多3项。
- 纠正旧回答时，原问答保持不动，在复盘写“旧结论 → 更正 → 理由 → 依据（教材／原题／推导）”；依据不足就写待核实。

## 可直接发给各科助手

> 你负责【科目】。先阅读本仓库AGENTS.md和该科历史交接，再读取`问答记录/【科目】/`的最近记录。以后每次答疑追加到该科当天问答。当我说“总结今天”，先看最近一份复盘的题目状态和“下次先做”；按`每日复盘/模板.md`提炼实际学习内容、逐题状态与证据、知识点、错误原因、闭卷自测（含迁移题）与明日动作，引用原记录，不混入其他科，不把计划写成完成。只在我授权时提交公开GitHub，先检查私人信息。网页无需另建一套知识库。

## 网页与保存边界

### 快速闭卷自测

进入本科「闭卷自测」即可使用已保存复盘里的自测题，不需设置或填表。先口述或写一句回想，再展开参考要点，自评“不会／模糊／会了”。

每张卡先展示完整的自测题干与必要代码、条件；答案在点击后才出现。「每日复盘」也采用相同的题干／答案分离。旧卡若没有题干字段，保持旧格式兼容，但各科助手在下次维护时应补齐。题干补充属于题目版本变更，会重新进入新题队列；旧版自评与草稿不删除，不自动当成新题已会。

使用透明的间隔重复规则（不是墨墨的内部算法）：

- 不会：10分钟后再出现，间隔等级重置。
- 模糊：1天后复习，间隔等级回退一级。
- 会了：在到期复习时逐级安排1、3、7、14、30、60天后再见，到60天后维持该间隔。
- 提前选择“练全部”不等于完成间隔复习；提前点“会了”保留原到期时间和等级，不能同一天连续点几次就跳到30天。提前发现不会／模糊则缩短间隔。
- 页面先列到期题，再列新题，并显示下一次时间（北京时间）。停留在本页且本轮答完后，每15秒检查一次到期题；不会打断正在写的回想。关闭页面不推送通知，下次打开会恢复待复习队列。

这些间隔是默认学习建议，不是精确的个人遗忘预测；能回想起一句结论也不等于能独立完成整道考题。

自评、可选回想仅存当前浏览器，可导出Markdown；不跨设备，不上传，也不会把题目状态升级为独立做对。没有自测题时保留空白。题目或参考答案修改后按新题重新自测，旧版浏览器记录不删除，但当前导出只含当前版本。

### 图解与源码

问答里的 fenced `svg` 代码块会显示成静态图，并支持点击放大；宽图放大后可以横向滚动。仅支持基础形状、文字、路径及渐变，脚本、事件、外链资源、CSS、foreignObject、动画等会被清除。复杂样式请由原助手先导出为PNG或简洁SVG，保留原始源码另供追溯，不要假称转换后逐像素一致。

HTML／React／JSX代码块折叠为源码，不在网页上执行。对话里生成的React图（含`<script type="text/babel">`的HTML）可在本机转换：存成文件后运行一次`npm install`，再执行`node scripts/render_diagram.mjs 源码.html 图解/科目/名称.svg`，得到不含脚本的静态SVG（颜色变量一并写入，可直接作为图片显示）；可另写同名`.md`说明图的结论、来源和待核实处。问答里用`![图名](../../图解/科目/名称.svg)`引用，该科「过往记录」顶部也会列出本科图解。转换只在本机执行源码，只转换可信的图。图解只能帮助回忆，图中的题意、公式和结论仍需有来源，不能把能渲染当作答案正确。

### 助手交互保持轻量

以用户当次要求为准：问“为什么”就直接解释，要求“直接讲”就给解法，不反复追问是否先做；只有明确要求训练时采用提示式引导。记录表由助手根据已出现的证据整理，不要求用户每次填写。迁移练习集中到日终复盘，不在每次答疑后强制加题。

网页提供科目、日期、问答／复盘／题目追踪／历史切换，闭卷自测、复制各科提示词及草稿导出。题目追踪汇总各天复盘里的状态表；它来自已提交的Markdown，所以换设备、换助手也能看到。草稿、已复习标记只存当前浏览器；下载Markdown后交给有仓库权限的助手审核上传。不要在公开仓库放账号凭据或私人聊天。

这不是后台自动读取Claude／ChatGPT的服务，也没有设置每日定时任务。当天总结由各科助手根据真实问答生成；规范Markdown提交到main后，网页会尝试读取GitHub最新目录，API限流时显示随站点发布的数据快照。更新页面不等于学习完成。
