## 08:15　`CO-寻址-01`　基址寻址（对比变址、相对）

**用户问题**：“基指寻址是什么忘了”

**讲解**
1. 基址寻址：EA = (BR) + A。BR 为基址寄存器，存基地址；A 为指令中的形式地址，作偏移量。
2. 用途：程序装入主存的位置不定，OS 把起始地址放进 BR，指令只写偏移，实现程序浮动（重定位）；短的 A 也能访问大地址空间。
3. 特点：BR 面向操作系统，由系统设定，用户程序执行中一般不改；A 由用户给出、可变。
4. 对比：

| | 公式 | 不变 | 变 | 面向 | 用途 |
|---|---|---|---|---|---|
| 基址 | (BR)+A | BR | A | 操作系统 | 重定位、扩大寻址范围 |
| 变址 | (IX)+A | A（数组首地址） | IX（下标，可自增） | 用户 | 数组、循环 |
| 相对 | (PC)+A | — | — | 随指令 | 转移、与位置无关代码 |

5. 易错：相对寻址的 PC 一般是取指后已更新（指向下一条指令）的值，看题目约定。

**检验**：按字节编址，指令长 2B，当前指令地址 2000H，(BR) = 1000H，(IX) = 0030H，A = 0020H。基址、变址、相对（取指后 PC 已加 2）的 EA 各是多少？待用户作答。

是否独立作答：本条为概念讲解，无作答。核对依据：王道 27 版第 4 章寻址方式，未逐页引用。

**08:19 用户作答（有提示）**：“ffffff12 + f0000000 + 3”。核对：列式正确（FF12H 正确符号扩展为 FFFF FF12H），未写最终结果。补全：FFFF FF12H + F000 0000H = 1 EFFF FF12H，舍去 32 位外进位，EA = EFFF FF12H；LSB 地址 = EA + 3 = EFFF FF15H，选 D（与王道 27 版第 4 章习题 31 答案一致）。快速验算：FFFF FF12H = −EEH，EA = F000 0000H − EEH。A、B 以 F000 开头，是把 FF12H 零扩展的结果。

## 15:28　`408-2010-43`　第 (2) 问转移目标地址范围

**题（原题，王道 27 版第 4 章综合题 03 所录 2010 统考真题）**：某计算机字长为 16 位，主存地址空间大小为 128KB，按字编址，采用单字长指令格式，指令字段 OP(15–12)、Ms、Rs、Md、Rd（各 3 位）。转移指令采用相对寻址方式，相对偏移量用补码表示；寻址方式 011B 为相对 D(Rn)：转移目标地址 = (PC) + (Rn)。(2) 转移指令的目标地址范围是多少？

**用户问题**：“10 年 43 题第二问这个范围怎么做的，我写的对吗”

**用户作答**（2026-10-10 整卷独立作答，见当日 17:52 记录）：[−2¹⁶ + Rn, 2¹⁶ − 1 + Rn]。
**核对**：错误。正确答案 0000H～FFFFH（整个主存）。核对依据：王道 27 版第 4 章综合题 03 解析（原件已核）。

**讲解**：主存 128KB ÷ 2B = 2¹⁶ 字，地址 0000H～FFFFH；PC 16 位可取 0～2¹⁶−1；Rn 为 16 位补码，−2¹⁵～2¹⁵−1；相加在 16 位内按模 2¹⁶ 回绕，可到达任一地址，所以范围是整个主存。

**错误步骤 → 更正**：把 Rn 当起点（起点应是 PC）；偏移量范围写成 ±2¹⁶（16 位补码是 ±2¹⁵）；没意识到结果是 16 位地址，不会超出 0～FFFFH。

**判断方法**：起点和偏移量都是满宽度寄存器 → 覆盖整个地址空间；偏移量来自指令中的短字段 → 只能到 PC 附近一段。

**检验**（换条件）：(PC) = 2000H，地址 16 位。(1) 偏移量为指令中 8 位补码时的目标范围；(2) 偏移量来自 16 位寄存器（补码）时的范围。待用户作答。

## 15:36　`408-2010-43`　第 (3) 问为什么先相加后自增

**题（原题，王道 27 版第 4 章综合题 03 第 3 问）**：若操作码 0010B 表示加法操作（助记符 add），R4、R5 编号分别为 100B、101B，R4 的内容为 1234H，R5 的内容为 5678H，地址 1234H 中的内容为 5678H，5678H 中的内容为 1234H，则汇编语句“add (R4), (R5)+”（逗号前为源操作数，逗号后为目的操作数）对应的机器码是什么？执行后哪些寄存器和存储单元的内容会改变？改变后的内容是什么？（寻址方式表 010B：(Rn)+，操作数 = ((Rn))，(Rn) + 1 → Rn。）

**用户问题**：“为什么先算的相加后自增，我是先自增后算的”

**讲解**：寻址方式表的定义是“先用、后增”：先以 Rn 的原值为地址取操作数、写回结果，再 Rn + 1，同 C 的 *p++。代入：源 ((R4)) = 5678H；目的以 R5 原值 5678H 为地址，取得 1234H；和 68ACH 写回主存 5678H 单元；之后 R5 = 5679H，R4 不变（王道解析，原件已核）。先自增会用 5679H 作地址，那是题目未定义的“先增”方式。记法：符号在括号后 (Rn)+ 先用后改；在括号前 -(Rn) 先改后用。

**错误步骤 → 更正**：先自增再取数 → 先以原值取数并写回，再自增。

**检验**（换条件）：同上初值，另设主存 5677H 中为 0001H；新增 -(Rn)：先 (Rn) − 1 → Rn，再以新 Rn 为地址取操作数。执行 add (R4), -(R5) 后，哪些寄存器和主存单元改变、改成多少？待用户作答。

## 15:40　`408-2010-44`　Cache 地址拆分、控制位与总容量（补漏 + 可视化）

**题（原题，王道 27 版第 3 章综合题 04 所录 2010 统考真题）**：某计算机的主存地址空间大小为 256MB，按字节编址。指令 Cache 和数据 Cache 分离，均有 8 个 Cache 行，每个 Cache 行大小为 64B，数据 Cache 采用直接映射方式。现有两个功能相同的程序 A 和 B（A 按行、B 按列对 int a[256][256] 求和）。假定 int 型数据用 32 位补码表示，i、j 和 sum 均分配在寄存器中，数组 a 按行优先方式存放，其首地址为 320（十进制数）。(1) 不考虑用于 Cache 一致性维护和替换算法的控制位，数据 Cache 的总容量为多少？(2) 数组元素 a[0][31] 和 a[1][1] 各自所在的主存块对应的 Cache 行号是多少（Cache 行号从 0 开始）？(3) 程序 A 和 B 的数据访问命中率各是多少？哪个程序的执行时间更短？

**用户问题**：“44 题这个直接映射是 tag 行号 块内地址，我这个给忘记了，还有类似的吗，我看还有控制位、LRU 位之类的一起补补，再就是会用到这种计算的，比如算总容量，帮我完善一下，放在服务器可视化页面”

**更正**：2026-10-10 17:52 记录把本题写成“回写方式、含脏位”，第 (1) 问算成 533 位 × 8 = 4264 位，有误。原题明确“不考虑一致性维护和替换算法的控制位”，每行只加有效位：8 × (1 + 19 + 512) = **4256 位**（王道解析原件已核）。第 (3) 问 A 的命中率 15/16 = 93.75% 已与王道解析核对。

**漏洞**：地址三段“标记｜行号｜块内地址”的来历记不住；控制位哪些一定有、哪些看题意不清；总容量只算数据区。

**补法**
1. 地址位数 = log₂(主存容量 ÷ 编址单位)；块内地址 = log₂(块大小 ÷ 编址单位)；行数 = 数据区 ÷ 块大小，组数 = 行数 ÷ 路数；中间字段 = log₂(组数)（直接映射叫行号，组相联叫组号，全相联没有）；标记 = 剩下的高位。
2. 每行控制位：有效位 1 位一定有；脏位 1 位只在回写时有；LRU 位只在 LRU 时有，位数 = log₂(组内行数)（2 路 1 位、4 路 2 位，王道 3.3 节）；题目说“不考虑一致性维护和替换控制位”就只算有效位。
3. 总容量 = 行数 × (控制位 + 标记 + 块大小 × 8)，单位是位；不含数据的部分是标记阵列。
4. 元素定位：地址 = 首地址 + 下标 × 元素大小 → 块号 = ⌊地址 ÷ 块大小⌋ → 组号 = 块号 mod 组数。
5. 本题：28 位 = 19｜3｜6；每行 1 + 19 + 512 = 532 位，总 4256 位；a[0][31] 地址 444 → 块 6 → 行 6；a[1][1] 地址 1348 → 块 21 → 行 5。

**可视化**：[Cache 地址与容量](../../演示/计算机组成原理/Cache地址与容量.html)（网站“可视化”目录中），三种映射的地址拆分条、一行结构条、总容量与标记阵列算式、数组元素定位，可开“闭卷”先算再看。预设 2010-44、王道例 3.3 改 2 路、王道第 3 章综合 01（68480 位）、综合 02（标记阵列全写 10752 位 / 回写 11264 位）均与王道解析核对。

**检验**（换条件，不重做原题）：主存 4GB、按字节编址；Cache 数据区 32KB，块 64B，8 路组相联，回写，LRU。(1) 地址三段各几位；(2) 每行几位、总容量多少位；(3) int b[64][64] 首地址 0040 0000H，b[2][17] 在第几组。另：2026-10-10 记录里的迁移题（64MB、16 行 × 32B、回写）仍待作答。

#### 三、讲得好、值得照着做的页

1. **第一章 p93–125**：同一个程序从指令表一路跟到每一拍寄存器的值。A1、F1 照这个做，用单步加寄存器面板。
2. **第二章 p55–60、p71–73、p102–104**：用 3 位机器数的“真值到机器数映射”统一解释原码、补码、移码。B1 照这个做。
3. **第二章 p174–178**：8 位无符号数画成 0～255 的环，解释取模、借位和 CF = sub⊕Cout。B2 用。
4. **第二章 p283**：迷你浮点格式的数轴，规格化数越往外越稀，非规格化数填在 0 附近。B6 用。
5. **存储器（下）p28–37**：轮流启动每 10ns 一页，配甘特图（p37 有手写标注）。C2 照这个做。
6. **存储器（中）p40–46**：LRU 计数器随访问序列逐次变化的表。C4 用。
7. **强化 4 p49**：用“存储器总线宽度和每个体的字长相不相等”判断同时启动还是轮流启动。C2 的判断规则用它。
8. **强化 3 p24、p28–30**：单周期数据通路的“无效数据流”，这个讲法少见，正好用两种颜色点亮。F2 用。
9. **强化 3 p42–52**：把单周期的一组控制信号拆到 EX、MEM、WB 各段。F3 用。
10. **第六章 p23–38**：取指、间址、执行的节拍表逐行展开。F1 用。
11. **第七章 p12–21**：用“演出排期”类比微操作（谁、哪天、上午还是下午），引出“按时间点控制”。适合放在 G1、G3 开头。
12. **强化 1 p14–23**：一道题串起 CPU 主频、总线带宽、交叉存储突发传送和 Cache 缺失。适合做成 C2 的综合预设。
13. **强化 2 p49–55**：指令与微指令模型（addm），把指令周期和微程序对应起来。G2 的预设用它。

#### 四、PPT 里要小心、不照搬的地方

1. **强化 5 p12、第六章 p63** 把超标量说成“多个核各有一条流水线”。袁春风第 3 版的定义是“动态多发射处理器也称为超标量处理器”，处理器内有多个功能单元，每周期可发射多条指令，和多核不是一回事。做 F3 时按教材定义。
2. **强化 4 p46** 例题答案写作“80us”，单位应为 ns；数值我没有复算，做 C2 时会按存储器（下）p28–37 的时间线方法重算再用。
3. **强化 5 p39** 用“擅不擅长分支语句”区分细粒度、粗粒度多线程，这不是教材定义；以前一页 p38 的定义（每条指令后切换，还是只在 Cache 缺失这类高开销阻塞时切换）为准。

#### 五、这套 PPT 没覆盖、需要从王道或袁春风补的

- 虚拟存储器：页表、TLB、虚实地址转换。强化 4 p5–9 列出 2016、2018、2019、2021、2023 年大题都涉及，但 16 份 PPT 里没有讲解页。
- 校验码（海明码、CRC）、磁盘与 RAID、总线仲裁方式：全文没搜到对应讲解。

如果要做这几块，可视化页面会以王道 27 版为依据，并注明来源。
