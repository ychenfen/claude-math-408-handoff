## 15:51　`408-2024-18`　哪个事件不在 MMU 地址转换中检测

**题（原题，王道 27 版第 3 章所录 2024 统考真题）**：下列事件中，不是在 MMU 地址转换过程中检测的是（ ）。A. 访问越权　B. Cache 缺失　C. 页面缺失　D. TLB 缺失

**用户问题**：“18题”。10/12 整卷独立作答选 A，错误，应选 B（用户红笔订正）。

**讲解**（答案 B，与王道解析一致）
1. MMU 只负责虚拟地址 → 物理地址；Cache 在得到物理地址之后才查。
2. 访存顺序：虚拟地址 → 查 TLB（缺失 = D）→ 查页表项（有效位 0 = 缺页 C）→ 检查权限位（越权 = A）→ 得物理地址，MMU 结束 → 查 Cache（缺失 = B）→ 访主存。
3. 选 A 的原因推测：以为越权要到访问数据时才发现。实际权限位就在页表项和 TLB 表项里，MMU 拿到表项时就检查。
4. 记法：MMU 管翻译，翻译用到的 TLB、页表、权限位出问题都归它；Cache 管取数，用翻译完的物理地址。

**检验**：一次访存中，“TLB 命中、Cache 缺失、缺页”三者能否同时发生？为什么？（即 10/12 20:27 检验题 (c)）待用户作答。

核对依据：王道 27 版第 3 章该题解析。

## 15:55　`CO-存储层次-01`　Cache—主存层次和主存—辅存层次是不是一回事（接 408-2024-16）

**用户问题**：引用上一条讲解里的“Cache 层次要的是快，虚存层次怕的是访问外存太慢”，问“啥意思，这俩层次一样吗”。

**讲解**
1. 不一样，是存储金字塔里相邻的两对：Cache（SRAM，几 ns）—主存（DRAM，几十～上百 ns）为一对，目的是让主存“看起来”像 Cache 一样快；主存—辅存（磁盘，毫秒级）为另一对，即虚拟存储器，目的是让主存“看起来”像磁盘一样大。主存是两对共用的中间层。
2. 相同点：同一个套路，把常用的复制到上面更快更小的一层，靠局部性原理命中，都有命中、缺失、替换、写回。
3. 不同点来自缺失代价：Cache 缺失多等几十个周期，所以全硬件、映射可简单（直接、组相联）；缺页要几毫秒（几百万个周期），交给 OS 软件处理并切换进程，并且尽量少缺页：全相联、只用写回、页做大。
4. 一句话：同一套路用在两对存储器上，下面那对慢得多，所以宁可多花软件和表格功夫也要少缺一次。

## 16:00　`CO-存储层次-02`　Cache 比 CPU 快吗

**用户问题**：“cache比cpu块吗”（接上一条存储层次图，图中 CPU 画在 Cache 上方）。

**讲解**
1. 不是，Cache 比 CPU 慢。CPU 是“用数据的”，Cache、主存、磁盘是“放数据的”，快慢是这些存储层互相比。
2. 由近到远：寄存器（CPU 内部，1 个周期内）→ Cache（L1 约 1～几个周期，L2/L3 十几到几十个周期）→ 主存（上百个周期）→ 磁盘（毫秒级，几百万个周期）。周期数是常见数量级，做题以题目给的为准。
3. Cache 的作用是比主存快得多、离 CPU 近，让 CPU 少等主存，不是比 CPU 快。

## 16:25　`CO-虚存-01`　TLB 在哪里

**用户问题**：“tlb是在哪里的”（接 2024-18 流程图）。

**讲解**
1. TLB 在 CPU 芯片里，是 MMU 的一部分，用高速 SRAM 构成（王道 27 版第 3 章：“缓存在由高速 SRAM 构成的快表（TLB）中”），查它不用访问主存。
2. 对比：TLB 在 MMU 内，存最近用过的少量页表项副本（虚页号 → 页框号、有效位、权限位）；页表（慢表）在主存，由 OS 建立维护，存进程全部页表项；Cache 在 CPU 里，存最近用过的数据和指令所在主存块的副本。
3. TLB 是“页表的 Cache”，加快地址翻译；Cache 加快取数。TLB 缺失慢在要多访问一次主存查页表。
4. TLB 一般全相联或组相联，靠标记比较查找；2024 年真题有一道算 TLB 表项标记位（32 表项、4 路组相联、虚拟地址 32 位、页 1KB，答案 19 位，王道解析）。

## 16:26　`CO-虚存-02`　算位数的几种结构：Cache 行、TLB 项、页表项

**用户问题**：“算位数的分别哪几种，我记得算出标记为加油存在为之类的”（语音输入，意为“标记位、存在位之类”）。

**讲解**：一项 = 查找用的部分 + 查到后要用的内容 + 控制位。
1. Cache 行（物理地址拆）：标记 ｜ 行号或组号 ｜ 块内地址；直接映射中间 log₂(行数)，k 路组相联 log₂(行数/k)，全相联无。一行 = 有效位 1 + 脏位（回写才有）+ 替换位（LRU 时 k 路每行 log₂k）+ 标记 + 数据。例 2010-44：28 位地址，块内 6、行号 3、标记 19，不计一致性和替换位，每行 1 + 19 + 512 = 532 位。
2. TLB 项（虚拟地址拆）：虚页号 = 标记 ｜ 组号；全相联标记 = 整个虚页号，组相联减去组号位。一项 = 有效位 + 标记 + 页框号（物理地址位 − 页内位），可能有权限、修改位。例 2024：32 位虚拟地址、页 1KB、32 项 4 路 8 组，标记 32 − 10 − 3 = 19。
3. 页表项：没有标记，虚页号直接作下标。一项 = 存在位（有效位）+ 页框号 + 修改位 + 访问位 + 保护位等，不在主存时记外存地址；一般凑整字节，页表大小 = 虚页数 × 项大小。
4. 易错：Cache 用物理地址拆、TLB 用虚拟地址拆；Cache 和 TLB 存标记，页表不存。

**检验**：主存地址 30 位，虚拟地址 32 位，页 4KB。(a) 页框号至少几位？(b) TLB 64 项全相联，标记几位？(c) Cache 64 行、块 32B、4 路组相联，标记几位？待用户作答。（参考：18、20、21。）

## 19:24　`CO-流水线-01`　转发（旁路）

**用户问题**：“转发旁路讲讲”。

**讲解**（依据第六章 p58，强化 3 p53–58）
1. 定义：后一条要用前一条的结果，但还没写回寄存器堆；不等写回，直接从段寄存器把结果送到 ALU 输入端。
2. 例（第六章 p58）：I1 add r3,r2,r1；I2 add r5,r4,r3。不转发时，靠“前半拍写、后半拍读”，I2 的 ID 最早在 I1 的 WB 拍，停 2 拍。转发时 I1 在 EX 末尾算出 r3，放在 EX/MEM 段寄存器，直接送进 I2 下一拍的 ALU，不停。I2 在 ID 读到的旧值不用，ALU 前的多路选择器改选转发值。
3. 检测：比较 EX/MEM、MEM/WB 段的目的寄存器与当前 EX 段的 rs/rt（且那条指令要写寄存器）；更早的靠前写后读解决。
4. load-use（强化 3 p58）：lw 的数据在 MEM 末尾才有，紧跟的指令即使转发也停 1 拍；编译器可插入无关指令填上。
5. 记法：ALU 算出来的下一条立刻能用，存储器读出来的晚一拍才能用。
6. 演示页：单周期数据通路与五段流水线，预设“写后读”“load-use”，切换转发对比。

**检验**：lw r2,0(r1)；add r3,r2,r2；sub r4,r3,r1。有转发时共停几拍、停在哪？待用户作答。（参考：1 拍，在 lw 与 add 之间；add → sub 转发不停。）

## 19:27　`CO-流水线-02`　数据冒险停几拍：分哪几种情况

**用户问题**：“分为哪几种情况，感觉有点乱”（接上一条转发讲解）。

**讲解**：按“写 r 的是 ALU 还是 lw”×“中间隔几条”×“有无转发”分（寄存器前半拍写、后半拍读，强化 3 p54）。

| 写 r 的指令 | 紧跟 | 隔 1 条 | 隔 ≥ 2 条 |
|---|---|---|---|
| ALU，不转发 | 停 2 | 停 1 | 不停 |
| ALU，有转发 | 不停（EX/MEM） | 不停（MEM/WB） | 不停 |
| lw，不转发 | 停 2 | 停 1 | 不停 |
| lw，有转发 | 停 1（load-use） | 不停（MEM/WB） | 不停 |

1. 不转发：等 WB 写回才能 ID 读，ALU、lw 一样。
2. 有转发：ALU 结果 EX 末尾就有，永远不停；lw 数据 MEM 末尾才有，只有紧跟使用停 1 拍。
3. 若题目规定同一拍不能既写又读，不转发两行各多停 1 拍（3、2、1）。
4. 套用上一条检验题：lw → add 紧跟有转发停 1；add → sub 不停；共 1 拍（已在回复中给出）。

## 19:33　`408-2024-20`　总线带宽：突发传送是干扰条件

**题（原题，王道 27 版第 6 章所录 2024 统考真题；题号为助手按计组选择题顺序推断，未与试卷照片核对）**：某存储器总线的时钟频率为 420MHz，总线宽度为 64 位，每个时钟周期传送 2 次数据；其总线事务支持突发传送方式，最多传送 8 次数据，第 1 个时钟周期传送地址和读/写命令，从第 4 个至第 7 个时钟周期连续传送 8 次数据。该总线的总线带宽（最大数据传输率）为（ ）。A. 3.84GB/s　B. 6.72GB/s　C. 30.72GB/s　D. 53.76GB/s

**用户问题**：“20题”。

**讲解**（答案 B，与王道解析一致）
1. 总线带宽 = 最大数据传输率，假设每个周期都在传数据，突发传送的描述是干扰条件。
2. 8B × 2 × 420M/s = 6.72GB/s（带宽的 M、G 取 10⁶、10⁹）。
3. 陷阱 A：一次突发事务 7 个周期传 64B，64B × 420M ÷ 7 = 3.84GB/s，是这种事务的实际平均传输率。陷阱 D：6.72 × 8，重复乘了 8 次传送。
4. 记法：问带宽只用宽度、每周期次数、频率；问实际或某次事务的传输率才数周期。

**检验**：同一总线一次突发读事务的数据传输率？待用户作答。（参考：3.84GB/s。）

## 19:37　`408-2024-21`　中断 I/O：响应优先级与处理优先级

**题（原题，王道 27 版第 7 章所录 2024 统考真题；题号与 10/12 考试记录一致）**：下列关于中断 I/O 方式的叙述中，错误的是（ ）。A. 中断屏蔽字用于确定中断响应的优先级　B. 保存断点和程序状态字在中断响应阶段完成　C. 保存通用寄存器和设置新中断屏蔽字由软件实现　D. 单重中断方式下中断处理时 CPU 处于关中断状态

**用户问题**：“21”。10/12 做题时选 A（正确）但拿不准。

**讲解**（答案 A，与王道解析一致）
1. 中断响应（硬件，中断隐指令）：关中断、保存断点 PC 和 PSW、找入口送 PC，所以 B 对。
2. 中断处理（软件，中断服务程序）：保存通用寄存器、设新屏蔽字，所以 C 对；多重中断此时开中断，单重中断整个处理期间关中断，所以 D 对。
3. A 错：响应优先级指同时请求时先响应谁，由硬件判优线路或查询顺序决定，不可变；处理优先级指能否打断正在处理的中断，由屏蔽字决定，可变。王道解析原话：“响应优先级由硬件线路或查询程序的查询顺序确定，不可动态改变；处理优先级由中断屏蔽字确定，可灵活改变。”
4. 记法：响应看硬件排队，处理看屏蔽字；PC、PSW 硬件保存，通用寄存器软件保存。

**检验**：中断屏蔽字能否改变两个中断的响应次序？能改变什么？待用户作答。（参考：不能；改变处理次序，即谁能打断谁。）
